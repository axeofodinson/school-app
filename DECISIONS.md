## 2026-11-25 — Android app size under 100 MB (Hassan)

82. **Android builds: three ABIs, compressed native libraries, R8 + resource shrinking** (`expo-build-properties` in `apps/mobile/app.json`). The 122 MB preview APK was a universal APK: JS + fonts are only ~8 MB (`expo export -p android`), the rest is native `.so` files for four ABIs, stored uncompressed (AGP default). Changes: `buildArchs` = `armeabi-v7a, arm64-v8a, x86_64` (32-bit `x86` dropped: only old emulators use it; Intel/AMD Chromebooks are `x86_64`, ARM Chromebooks `arm64-v8a`; `armeabi-v7a` stays for cheap 32-bit/Android Go phones); `useLegacyPackaging: true` (native libs compressed inside the APK: smaller file, slightly larger once installed); `enableMinifyInReleaseBuilds` + `enableShrinkResourcesInReleaseBuilds` (R8 drops unused Java/Kotlin code and resources). Expected: the APK roughly halves (≈ 50–65 MB, **unverified until the next preview build**). The Play Store AAB (`production` profile) is split per device, so a download is one ABI and usually ≈ 25–35 MB. Not changed: the JS bundle isn't compressed (`enableBundleCompression` slows cold start; budget < 5 s); `expo-dev-client` already compiles to no-op stubs in release builds; the old app's root deps (expo 51, expo-av, expo-notifications) are not autolinked into `apps/mobile` (checked with `expo-modules-autolinking resolve`), so they add nothing to the APK. Risk: R8 can strip a class a library loads by reflection; if a release build crashes on start or on one screen, set the two minify flags to false first.

## 2026-11-25 — cut-over: answer keys closed, server marking (session 13)

78. **`db/018_close_answer_key_read.sql` (draft): students can't read `questions` at all.** `p_questions_read` becomes staff + teachers only (017 Part 10's plan). Column grants can't do it (teachers and students share the `authenticated` role) and a view would still need a policy per caller, so students get two SECURITY DEFINER reads that never return `answer`: `student_paper(assessment)` (id, type, body, marks, order, level; same visibility as db/005's paper policy: published, own class + year) and `student_paper_levels(ids[])` (marks + level for the report card, published or closed). Parents, pending and prep-only users read 0 rows too. Numbered 018 as planned, but it runs after 026. **Run at the cut-over only:** the old app's student test screen reads `questions` and shows an empty paper afterwards (accepted, DECISIONS #22); its teacher/admin screens are unaffected. — Claude, session 13.
79. **Auto-marking happens on the server, in an AFTER INSERT trigger on `submissions`, not a new submit RPC.** The app keeps its plain insert (client UUID, offline queue, duplicate = done, no app change to the sync path) and the old app's submissions get marked too. A paper is marked only when every question is auto-markable (mcq, true_false, numeric, short_text, tap_image with a usable `correct`); anything else (match, multi_select, a key without `correct`, file worksheets, a score above the test's total) stays "not marked" for the teacher, as before. Score = sum of the marks of correct answers; `graded_by = null` (system), `graded_at = now()`, and one `submission_grade_edits` row (`reason = 'Auto-marked'`, `edited_by = null`), so a teacher's later change is a correction with a reason through `record_grade()` (rule 3; it stays the only path for people). Only the student's own attempt is marked (the enrollment must be the caller's, `my_student_id()`): a teacher/admin row with responses gets no system mark, so every person-entered grade carries their name (security review, session 13). Marking is graded against the question's current key (questions aren't versioned until 017). Errors in marking never refuse the attempt: it is kept unmarked with a warning. The trigger function can't be called through the API (trigger functions can't be called directly). — Claude, session 13.
80. **One marking rule, two implementations, one fixture.** `packages/core/src/autoMark.ts` (`autoMarkItem`, `autoScore`) and SQL `auto_mark_item()` are pinned by the same 34 cases in `packages/core/test/fixtures/auto-mark-cases.json` (vitest + `db/test/018_smoke.sql`). Rules: mcq/tap_image exact key; true_false booleans only; numeric = typed text with Latin or Urdu/Arabic digits, `.` or `٫`, spaces ignored, numerically equal (`42.0` = 42; junk = wrong; a non-number key = teacher marks); short_text per DECISIONS #64. Known gap: exotic Unicode spaces other than NBSP are collapsed by JS `\s` but not by Postgres; a student would see a "wrong" a teacher can correct. — Claude, session 13.
81. **Students see an auto mark as soon as the attempt syncs**, including on tests and exams (there is no "release results" flag yet). If teachers want results held back, that is a new assessment setting (a later prompt, e.g. 51). The teacher's history shows the auto mark as "Marked by the app when the student sent it" (Urdu string `// TODO: ur`). — Claude, session 13.

## 2026-11-24 — file worksheets, grading with audit, report card (session 12)

73. **`db/026_grade_write_guard.sql` (draft): grades change only through `record_grade()`.** setup.sql's `p_subs_staff`/`p_subs_teacher` are `FOR ALL`, so a teacher or admin could `update submissions set score = …` (no history, no reason) or delete a submission (grade + raw responses gone) from the browser console, bypassing db/013's audit. RLS can't say "only via this function", so a BEFORE INSERT/UPDATE/DELETE trigger refuses those columns and deletes when `current_user` is `authenticated`/`anon`; inside `record_grade()` (SECURITY DEFINER, owner `postgres`) and for the SQL Editor/service role/011/017 RPCs it does nothing. Side effect, intended: a client can no longer delete an assessment or enrollment that has submissions (the cascade would erase marks; rule 3). Nothing in the old or new app writes those columns directly (old: ungraded insert only), so the old app keeps working. GR-1 fails at `TEACHER_BYPASSED_RECORD_GRADE` without it.
74. **Grading UI = a grid per assessment, every save through `record_grade()`.** One score field per student (roll order, unnumbered last); the reason field appears only when changing an existing grade and is required before the RPC is called (the RPC re-checks); history opens inline (old → new, reason, date; staff/teacher only, students never see it). Only published and closed assessments are offered (a draft isn't visible to students). **Online-only for now:** grades aren't queued in the sync queue (a failed save keeps the typed value and says why; the teacher retries). Teachers grade on Windows PCs in school; queuing can come with prompt 61 if needed.
75. **"Graded before the attempt" is shown, not changed.** Entering a grade for a student with no submission on an open question paper creates the row, so their later online attempt is refused as a duplicate (responses not stored; DECISIONS #68 follow-up). The grid warns before saving (`gradeBlocksAttempt`); behaviour is unchanged (paper tests graded by hand are a real case).
76. **Worksheet files: `{assessment_id}/{uuid}.{ext}` in the private `assessment-files` bucket, ≤ 10 MB, images/.md/PDF/Office/text.** A fresh uuid per upload, so replacing a file never overwrites the old object (nothing deleted). The file uploads before a publish, so students never see an empty worksheet; publishing needs the file (`needFile`). Total marks optional (1–1000, whole), fixed once published. Upload bytes are sent as an ArrayBuffer (storage-js ignores `contentType` for Blob/File bodies). Viewing needs a connection (signed URL, 1 h); markdown is parsed in-app (core port of the old parser; only http(s)/mailto links open). The limits are client-side only for now (follow-up: bucket `file_size_limit` + `allowed_mime_types`).
77. **Report card + overdue math = the old app's, ported to `packages/core/src/reporting`** and tested side by side with the frozen `src/reporting/*.js` on the verify fixtures plus 300/200 seeded random fixtures (identical output). One deliberate difference: a cognitive level named like an Object prototype key (`toString`) is ignored instead of corrupting the totals. The student report reads the same device copy as the tests list (works offline once refreshed; a pre-12 device copy reads as "not available offline"), and the cognitive part loads online only.

## 2026-11-24 — student attempts, offline-safe (session 11)

68. **One durable queue per user in `packages/core/src/sync`, grown from the old `attemptStore`.** It lives in the user's queue namespace (`userQueueStore`, survives sign-out, only that user's next sign-in flushes it). Each item has a client UUID (v4, Web Crypto or a `Math.random` fallback) that the sender uses as the **row id**, and a `key` (identity, e.g. `enrollment:assessment`); re-queueing the same key replaces the payload but keeps the id. Outcomes: `ok`/`duplicate` (23505/409) remove it; `retry` (network, timeout, 5xx/429, expired JWT) backs off 2 s → 5 min with equal jitter and stops the pass; `reject` (RLS 42501, check constraints) keeps it marked for a person to see and is only retried when someone taps "try again", never silently dropped. Concurrent flushes share one pass; read-modify-write is serialised. Sends happen on start, foreground, the browser `online` event and when a backoff ends (capped at 60 s since native has no online event without a new dependency). Exactly one submission rests on two server keys: the client-UUID primary key and `unique(enrollment_id, assessment_id)`.
69. **Drafts live in the queue namespace too**, not the wipeable user namespace: an unsent draft is the student's own work and must survive an idle logout in the lab (10 min); it is still never visible to the next student. The draft is cleared once the submission is queued (the queue then holds the answers).
70. **`db/025_student_attempts_own_class.sql` (draft) ties a student's submission to their own class + year and an active enrollment.** db/005 checked "own enrollment" and "published assessment" separately; because students can read the assessments of every class they were ever enrolled in, a promoted student could file this year's enrollment against last year's class's test, and a struck-off enrollment could still submit. The smoke shows both (fails at `STUDENT_SUBMITTED_OTHER_CLASS` without 025). 025 also lets students read **closed** assessments of their class (not drafts) so results keep their titles; closed papers' questions stay hidden.
71. **Offline start uses the last good profile.** `AuthProvider` keeps the profile in the user's namespace (wiped at sign-out), shows it at once, then refreshes it; a network failure keeps the cached copy instead of the profile-error screen. Routing only; RLS still decides. Student reads in `features/attempts/api.ts` turn off postgrest-js's built-in GET retries (≈7 s offline) because they fall back to the device copy and have a Retry button.
72. **Student attempt screen = one scrolling paper for every type** (mcq, true_false, numeric, short_text typed, tap_image as big picture tiles with read-aloud: recorded clip on web when `prompt_audio` is a full URL, else device speech via `expo-speech` / `speechSynthesis`; Urdu only with an Urdu voice, otherwise the English prompt). The paged pre-reader experience is prompt 16. Formal tests and exams render in `<ExamMode>`. Blank answers warn once ("Submit anyway"). `responses` keeps the old shape (version 1) with `short_text` added as a trimmed string.

## 2026-11-24 — quick generate is the main way to make a paper (Hassan)

67. **Assessments are normally generated, not hand-built: class + subject → blueprint → Publish (3 clicks).** Hassan will import thousands of MCQs per subject (prompt 21 importer, not the authoring form), so a test, quiz, exam or assignment is drawn at random from approved items. Built in prompt 50 (needs 017 for topics, difficulty and approvals). — Hassan + Claude, after session 10.

## 2026-11-24 — question authoring + assessment builder (session 10)

64. **`short_text` answer shape: `answer = {"correct": "<model answer>", "also": ["<other accepted>", …]}`, body `{stem}`.** No shape existed before (the old app never authored it). `correct` keeps every type's key under the same name; `also` is optional, deduped, max 10. Matching (`shortTextMatches` in core, for prompt 11's grading) ignores case, extra spaces and Urdu/Arabic digits. Anything fuzzier (spelling tolerance) is a teacher regrade, not auto-marking. — Claude, session 10.
65. **Builder lifecycle and history rules (app-side, no schema change).** (a) Status moves are draft → published → closed ↔ published; never back to draft. (b) The question set, marks and type are fixed once published (title, weightage and date stay editable): students may have answered it (rule 7). (c) Create = insert as **draft**, add the questions, set `total_marks`, then publish; a later failure leaves a draft the teacher can fix. Nothing deletes an assessment (teachers have no DELETE policy, and the old app's rollback-by-delete would fail for them). (d) A question already in a published/closed assessment opens read-only with "Make a copy". This lock is **advisory**: RLS hides other classes' assessments from a teacher, so a use there isn't seen, and the DB still lets an owner update the row. The real fix is 017's append-only `question_versions` (attempts point at a version); until then the gap is accepted. (e) `file` worksheets stay in the old console until prompt 12. — Claude, session 10.
66. **Teacher scope in the new app = this year's `teacher_assignments`, narrowed to the assigned subjects** (a class-wide assignment, `subject_id` null, opens every subject). RLS (`teaches_class`) is class-level and year-blind, so this is UI convenience only; admins/developers see every class. Shared screens live in a new `(staff)` route group guarded for teacher + admin. — Claude, session 10.

## 2026-11-24 — nightly backups (OPS-backup)

63. **Backups = GitHub Actions `pg_dump` → `age` → release asset in a private repo** (`.github/workflows/db-backup.yml`, `scripts/backup/`, guide `docs/backup-restore.md`). Shape choices: (a) **two custom-format dumps from one exported snapshot**: `app.dump` = every app schema in full, `supabase.dump` = only `auth.users`, `auth.identities`, `storage.buckets`, `storage.objects` (pg_dump ignores `--schema` when `--table` is given, and dumping all of `auth`/`storage` would clash with what a fresh project already has); row counts read the same snapshot, so a restore can prove completeness exactly. (b) **Restore only into an empty project**: `restore.sh` refuses any target with app tables or auth users (that is the production guard), loads rows with `session_replication_role = replica` so the sign-up trigger doesn't fire on restored users, skips `DEFAULT ACL` and the `public` schema itself, re-adds Realtime publication membership (pg_dump `--schema` drops it), restores our triggers/policies on auth/storage tables only where missing, then diffs row counts. (c) **Retention** 14 daily + 8 weekly by tag date (`prune.mjs`, unit-tested); `keep-*` tags (manual run with `keep_label`, e.g. before OPS-remove-legacy) are never pruned. (d) **Private key offline only** (printed + 2 USB sticks), optional second trustee key. (e) Session pooler (:5432) because the direct host is IPv6-only and runners lack IPv6; transaction pooler refused (snapshot needs a session). (f) Failures open an issue in this repo, because GitHub's own failure mail goes to whoever last edited the cron (a Claude commit). (g) Weekly keep-alive REST read is a separate workflow, off until `KEEPALIVE=on`. **Not covered:** Storage file contents, Auth dashboard settings, Edge Function secrets (checklist in the guide; file backup is a follow-up).

The old app never writes `profiles` from a client, so nothing in it changes. Separate trigger name from 023's `profiles_guard`, so the two coexist and run order doesn't matter. Numbered 024 even though it runs before 017–023 in production (018–022 are planned/drafts); every file is idempotent and independent of that order. Reproduced first: without 024 a student's `update profiles set role = 'developer'` succeeds in the harness. After running, Hassan checks the staff list with the read-only query in the file's header. **Applied to production 2026-11-24 by Hassan; the staff-list check showed only his own accounts (no sign the hole was used).**

57. **Tiers live on `profiles.access_tier` (`school` | `prep_only`), enforced by RESTRICTIVE RLS** (`db/023`, draft, needs 017). `is_school_member()` is ANDed onto every school table (students, enrollments, teacher assignments, assessments + questions, submissions + grade edits, attendance, messages, push tokens, exam sessions/answers/events, project teams/scores), the old `questions` table (answer keys) and the two school storage buckets. Existing permissive policies already return 0 rows to an account with no `student_id`; the restrictive layer keeps that true whatever a later policy says (the smoke test adds a deliberately leaky policy to prove it). Learning tables (017) stay `learner_id = auth.uid()` for everyone. A prep-only profile is always role `student` with no `student_id` (check constraint), and the tier is one-way: nothing, not even staff SQL, turns a prep-only account into a school one.
58. **Only Google creates prep-only accounts, and Google never reaches a school or staff account.** `handle_new_user_v2()` (the auth trigger now points at it; setup.sql's function is untouched) makes a `google` sign-up a prep-only student; email, anonymous or any other provider stays `pending` as before. A trigger on `auth.identities` refuses to attach any OAuth identity to a school/staff account or to a pending account with a password or email identity, which also blocks Supabase's automatic linking of a Google account to a staff member with the same Gmail address (the sign-in fails; the app says "use your school login"). The app re-checks after the code exchange and signs a non-prep account straight out (covers a server without 023). Client flow: PKCE everywhere; native opens a Custom Tab with `expo-web-browser` and redirects to `schoolapp://auth-callback`; web redirects the page to `/auth-callback`, which exchanges the code and strips it from the address bar. Google is **not offered in shared-device mode** (school devices use school logins, and a memory-only session can't survive the web redirect). Why not `@react-native-google-signin`: needs extra Google Cloud/SHA-1 setup per build; the browser flow needs only a Web client in Supabase. Revisit if the Custom Tab UX is poor on Chromebooks.
59. **Upgrade path: staff link a prep account to the student's school login; history moves, the Google account stays prep-only.** `link_prep_account(prep, student_id, reason)` (staff only) re-keys `practice_attempts` to the school login (content unchanged, only the owner; this is the one sanctioned re-key of learning history), moves `concept_mastery` rows the school login doesn't have and follow-ups that don't clash with an open one, and leaves `gate_overrides` (append-only history of that account) and clashing rows on the prep account. Every link is logged in insert-only `account_links` (who, when, reason, counts). Re-running for the same pair moves stragglers (a late offline queue). The prep profile gets `merged_into`, and its home says where the practice went. The student must already have a school login (PIN). Prompt 40's mastery RPCs must recompute the school login's mastery after a link. Admin screen: `/link-prep` (search by email/name via `find_prep_accounts()`, find student by admission number).
60. **Closed a pre-existing privilege escalation:** setup.sql's `p_profiles_self_update` let any signed-in user update their own `role` (e.g. to `developer`). 023's `profiles_guard` trigger lets non-staff client sessions change only `full_name`/`phone` on their own row. With public Google sign-up this would have been exploitable by anyone, so it ships with 023. **The same hole exists in production today**; fixed for production by `db/024` (#62).
61. **Prep-only relief is automatic only** (`reliefPolicyFor('prep_only')` in core: auto relief, no teacher overrides, no exam follow-ups, nobody notified). Feature gating is `canUse(tier, feature)`; prep-only users get a `(prep)` route group (`/prepare`) with an explicit "School features" card instead of silently missing tabs.

## 2026-11-24 — login rebuilt (session 03)

48. **Login on the new app reuses the backend unchanged.** Student: `student_login_email(admission no)` then `signInWithPassword(synthesized email, PIN)`; staff: email + password. Flows are pure functions in `packages/core/src/auth/login.ts` with the Supabase calls injected (tested in Node). A `user_banned` error (db/009: no active enrollment) shows "your login is switched off", not "wrong PIN"; rate-limit and network errors are distinct too. Admission numbers and PINs accept Urdu digits (۰–۹). PINs are 4–8 digits (old app allowed up to 8); `PinField` got a `minLength` so boxes grow as digits are typed.
49. **Routing = `Stack.Protected` guards in `app/_layout.tsx`** driven by `destinationFor()` (core): signedOut → `(auth)`, student (needs `student_id`) → `(student)`, teacher → `(teacher)`, admin/developer → `(admin)`, pending/parent/unknown/no profile → `(account)/pending`, unreadable profile → `(account)/profile-error`. `index.tsx` redirects. Convenience only; RLS is the boundary. **Prompt 05 extension point:** `destinationFor` already returns `'prep'` for `access_tier = 'prep'` (sent to `/pending` for now); add `googleSignIn()` in `features/auth/AuthProvider.tsx` and select `access_tier` once the column exists.
50. **QR cards: payload `ASHS:<admission no>`, never a PIN.** The prefix lets the scanner ignore unrelated codes. QR encoding uses the bundled `qrcode` package; drawing (`qrPath`/`qrSvg`) and the A4 sheet (`cardSheetHtml`, 10 ID-1 cards per page, all text escaped) are in core and round-trip tested with jsQR. Admin route `/qr-cards` (active enrollments, filter by class) prints via a hidden iframe on web and `expo-print` on Android. **Scanning:** Android uses `expo-camera`; web scans only where the browser has a native `BarcodeDetector` (Chrome on ChromeOS/Android), because expo-camera's web polyfill (`barcode-detector` → `zxing-wasm`) downloads its WASM from jsDelivr (CLAUDE.md: no CDN). Elsewhere the scan screen falls back to typing. The polyfill code is still in the bundle as a lazy 44 KB chunk that our gate never loads.
51. **Shared-device mode and storage.** A per-device flag (`ns/device/sharedMode`, admin toggle in Settings) switches the Supabase session store from SecureStore (Android, chunked: values > 2 KB) / localStorage (web) to memory only, so nothing is remembered across restarts. Shared mode adds a 10-minute idle sign-out (touch/keys/pointer, checked every 15 s and on resume) and a big **Switch student** bottom bar on student screens. Per-user data lives in `ns/u/<userId>/…`; the sync queue in `ns/u/<userId>/queue/…`. **Every** sign-out (any mode, any cause, including a revoked refresh) wipes the user's namespace except the queue; in shared mode each sign-in also purges other users' non-queue leftovers. Sign-out uses `scope: 'local'` (works offline, doesn't log the student out of their own phone). Not yet: queue encryption at rest (LMS_AUDIT §3.3; prompt 61), pausing idle logout during an exam (prompt 50 must suspend it inside `<ExamMode>`), flush-before-logout warning (no queue exists yet; prompt 11).
52. **Settings screen** (`/settings`, any signed-in user): language, motion full / lite / off / auto (satisfies #47's WCAG 2.2.2 requirement), and the shared-device toggle (admins only; others see the state).

Components never call Reanimated with their own numbers: they name a **moment** (`useEnterStyle('toast', visible, { translateY: 16 })`, `usePressMotion(depth)`, `usePulse('skeleton')`), and `ui/motion.ts` resolves it through the tier and exam mode. Only the props the resolved behaviour lists move, so lite automatically becomes a fade and off/exam snap to the end state. Removing Moti also removes a hoisted package that needed the Metro singleton pins.
42. **Tokens live in `packages/core/src/design/`** (`tokens.ts`, `motion.ts`), not in `apps/mobile/ui/` as #35 planned; `apps/mobile/ui/tokens.ts` re-exports them and `ui/motion.ts` adds the Reanimated glue. Why: they are pure data + pure functions (tier picker, `resolveMoment`, `presentationForGrade`, `textMetrics`, `isolateLtrRuns`, contrast), so they are unit-tested in Node with vitest (121 core tests) and stay React-free. `docs/design/tokens.draft.ts` and `scripts/verify-design-tokens.mjs` are deleted; their checks are `packages/core/test/design-*.test.ts`. CLAUDE.md's "use only the tokens in `apps/mobile/ui/motion.ts`" still holds (that file re-exports them).
43. **Icons: Lucide path data copied into `ui/icons.data.ts`** (30 icons, ~6 KB, ISC licence noted in the file) and drawn with `react-native-svg`, instead of `lucide-react-native`, whose barrel import would put ~1,900 icons in the bundle (cold-start budget on 4 GB Chromebooks). Mastery band shapes are our own SVGs (`MasteryShape`).
44. **Tier and exam rules in the components.** The tier is computed per subtree against the nearest theme's presentation, so staff screens default to lite (`(teacher)`/`(admin)` layouts set `presentation="staff"`). OS reduce-motion always wins, even over a gallery/user "full". `<ExamMode>` resolves every moment except `examTimerTick`/`examSaveIndicator` to none **and** drops decoration: no tile patterns (`PatternBand` becomes a plain fill) and no sticker shadows. A toast raised inside an exam keeps the exam's no-motion rule. Sticker shadows are a separate static layer so a press moves only the face (transform); selected fills in segmented controls fade as their own layer (colour cross-fade done with opacity). Root stack transition follows the tier (`default` / `fade` / `none`). Not built yet: the frame-drop sampler (prompt 62), haptics (moments list them; wire `expo-haptics` with the practice engine, prompt 31), the bundled Lottie burst (full-tier celebration falls back to a gentle spring until it exists).
45. **Sheet = React Native `Modal`**, bottom sheet on phones and a centred dialog from 600 px, closing on the close button, Android back, Esc (web) and the scrim. Not `@expo/ui` BottomSheet, because we need one look on Android and web. Closing is instant (no exit animation) for now.
