## 2026-11-24 — Google sign-in + prep-only tier (session 05)

57. **Tiers live on `profiles.access_tier` (`school` | `prep_only`), enforced by RESTRICTIVE RLS** (`db/023`, draft, needs 017). `is_school_member()` is ANDed onto every school table (students, enrollments, teacher assignments, assessments + questions, submissions + grade edits, attendance, messages, push tokens, exam sessions/answers/events, project teams/scores), the old `questions` table (answer keys) and the two school storage buckets. Existing permissive policies already return 0 rows to an account with no `student_id`; the restrictive layer keeps that true whatever a later policy says (the smoke test adds a deliberately leaky policy to prove it). Learning tables (017) stay `learner_id = auth.uid()` for everyone. A prep-only profile is always role `student` with no `student_id` (check constraint), and the tier is one-way: nothing, not even staff SQL, turns a prep-only account into a school one.
58. **Only Google creates prep-only accounts, and Google never reaches a school or staff account.** `handle_new_user_v2()` (the auth trigger now points at it; setup.sql's function is untouched) makes a `google` sign-up a prep-only student; email, anonymous or any other provider stays `pending` as before. A trigger on `auth.identities` refuses to attach any OAuth identity to a school/staff account or to a pending account with a password or email identity, which also blocks Supabase's automatic linking of a Google account to a staff member with the same Gmail address (the sign-in fails; the app says "use your school login"). The app re-checks after the code exchange and signs a non-prep account straight out (covers a server without 023). Client flow: PKCE everywhere; native opens a Custom Tab with `expo-web-browser` and redirects to `schoolapp://auth-callback`; web redirects the page to `/auth-callback`, which exchanges the code and strips it from the address bar. Google is **not offered in shared-device mode** (school devices use school logins, and a memory-only session can't survive the web redirect). Why not `@react-native-google-signin`: needs extra Google Cloud/SHA-1 setup per build; the browser flow needs only a Web client in Supabase. Revisit if the Custom Tab UX is poor on Chromebooks.
59. **Upgrade path: staff link a prep account to the student's school login; history moves, the Google account stays prep-only.** `link_prep_account(prep, student_id, reason)` (staff only) re-keys `practice_attempts` to the school login (content unchanged, only the owner; this is the one sanctioned re-key of learning history), moves `concept_mastery` rows the school login doesn't have and follow-ups that don't clash with an open one, and leaves `gate_overrides` (append-only history of that account) and clashing rows on the prep account. Every link is logged in insert-only `account_links` (who, when, reason, counts). Re-running for the same pair moves stragglers (a late offline queue). The prep profile gets `merged_into`, and its home says where the practice went. The student must already have a school login (PIN). Prompt 40's mastery RPCs must recompute the school login's mastery after a link. Admin screen: `/link-prep` (search by email/name via `find_prep_accounts()`, find student by admission number).
60. **Closed a pre-existing privilege escalation:** setup.sql's `p_profiles_self_update` let any signed-in user update their own `role` (e.g. to `developer`). 023's `profiles_guard` trigger lets non-staff client sessions change only `full_name`/`phone` on their own row. With public Google sign-up this would have been exploitable by anyone, so it ships with 023. **The same hole exists in production today** (school accounts only); consider running Part 3 of 023 early (see prompts/README note).
61. **Prep-only relief is automatic only** (`reliefPolicyFor('prep_only')` in core: auto relief, no teacher overrides, no exam follow-ups, nobody notified). Feature gating is `canUse(tier, feature)`; prep-only users get a `(prep)` route group (`/prepare`) with an explicit "School features" card instead of silently missing tabs.

## 2026-11-24 — synthetic seed (session 04)

53. **Seed rows are found by marker where `is_test_data` doesn't exist yet.** Before 017 only `students`/`profiles`/LMS tables can carry the flag (and only once 017 runs), so the seed marks the older tables by name instead: year `TEST 2026-27`, classes `TEST <class>-<section>`, admission numbers `TEST-NNNN`, staff emails `@seed.school.invalid`, curriculum `TEST-PTB`; everything else is a child of one of those. `scripts/seed/src/inventory.ts` is the one definition both the seed report and `remove.ts` use, so "what is seed data" can't drift between them. No new migration just for a test flag. Removal is a test-data-only hard delete in one transaction; for the append-only tables (`question_versions`, `learning_content_versions`, `gate_overrides`) it disables the forbid-mutation trigger for that one delete and re-enables it before commit (needs table ownership: the `postgres` role on Supabase). Never used for real data (CLAUDE.md rule 3/7 still hold).
54. **The seed writes over a direct Postgres connection, not the REST API.** It has to create auth users and call `provision_student_login()` (which checks `is_staff()`), so it sets `request.jwt.claim(s)` to the seed admin inside its transaction. No service-role key is needed; the dev project's DB password (session-pooler URL) is. Target guard: production ref refused outright; otherwise local hosts or an allow-listed dev ref only; and it refuses any database with > 50 non-TEST students. Students get one shared dev PIN (`1234`) and staff one dev password, overridable by env.
56. **Paste-ready seed SQL for the dev project.** Hassan found the terminal route (node + DB password on his PC) too much, so `npm run seed:sql` also writes `scripts/seed/sql/seed-dev.sql` and `remove-dev.sql` to paste into the dev project's SQL Editor, the way migrations are already run. They are generated from the same generators and inventory (a test fails if stale), cover the school part only (the LMS part is too big for the editor; `seed.ts` adds it on top later), and stop if the database has > 50 real students. The production-ref check can't live in a pasted file, so that real-student check is its guard.
55. **Seed shape choices.** PG + Classes 1–10, two sections each (22 class rows of 29–30; the old app models a section as its own `classes` row). The TEST year is made current (the app reads the current year); `remove` hands "current" back to the newest remaining year. The LMS content hangs off `TEST Class 9-A`'s subjects, since chapters belong to one class row's subject. 9-B's learners practise the same topics (topics are readable by any signed-in user) and their exams use 9-B's own subject rows. **Open for prompt 20:** sharing one curriculum across sections of a grade (today it needs duplicate chapters or a grade-level scope). Past exams are seeded as closed `live_exam` assessments with graded sessions but **no `submissions`** (results not confirmed through `record_grade()`), so grade-book screens show them as unconfirmed. History uses a fixed anchor date so it is deterministic.

## 2026-11-24 — login rebuilt (session 03)

48. **Login on the new app reuses the backend unchanged.** Student: `student_login_email(admission no)` then `signInWithPassword(synthesized email, PIN)`; staff: email + password. Flows are pure functions in `packages/core/src/auth/login.ts` with the Supabase calls injected (tested in Node). A `user_banned` error (db/009: no active enrollment) shows "your login is switched off", not "wrong PIN"; rate-limit and network errors are distinct too. Admission numbers and PINs accept Urdu digits (۰–۹). PINs are 4–8 digits (old app allowed up to 8); `PinField` got a `minLength` so boxes grow as digits are typed.
49. **Routing = `Stack.Protected` guards in `app/_layout.tsx`** driven by `destinationFor()` (core): signedOut → `(auth)`, student (needs `student_id`) → `(student)`, teacher → `(teacher)`, admin/developer → `(admin)`, pending/parent/unknown/no profile → `(account)/pending`, unreadable profile → `(account)/profile-error`. `index.tsx` redirects. Convenience only; RLS is the boundary. **Prompt 05 extension point:** `destinationFor` already returns `'prep'` for `access_tier = 'prep'` (sent to `/pending` for now); add `googleSignIn()` in `features/auth/AuthProvider.tsx` and select `access_tier` once the column exists.
50. **QR cards: payload `ASHS:<admission no>`, never a PIN.** The prefix lets the scanner ignore unrelated codes. QR encoding uses the bundled `qrcode` package; drawing (`qrPath`/`qrSvg`) and the A4 sheet (`cardSheetHtml`, 10 ID-1 cards per page, all text escaped) are in core and round-trip tested with jsQR. Admin route `/qr-cards` (active enrollments, filter by class) prints via a hidden iframe on web and `expo-print` on Android. **Scanning:** Android uses `expo-camera`; web scans only where the browser has a native `BarcodeDetector` (Chrome on ChromeOS/Android), because expo-camera's web polyfill (`barcode-detector` → `zxing-wasm`) downloads its WASM from jsDelivr (CLAUDE.md: no CDN). Elsewhere the scan screen falls back to typing. The polyfill code is still in the bundle as a lazy 44 KB chunk that our gate never loads.
51. **Shared-device mode and storage.** A per-device flag (`ns/device/sharedMode`, admin toggle in Settings) switches the Supabase session store from SecureStore (Android, chunked: values > 2 KB) / localStorage (web) to memory only, so nothing is remembered across restarts. Shared mode adds a 10-minute idle sign-out (touch/keys/pointer, checked every 15 s and on resume) and a big **Switch student** bottom bar on student screens. Per-user data lives in `ns/u/<userId>/…`; the sync queue in `ns/u/<userId>/queue/…`. **Every** sign-out (any mode, any cause, including a revoked refresh) wipes the user's namespace except the queue; in shared mode each sign-in also purges other users' non-queue leftovers. Sign-out uses `scope: 'local'` (works offline, doesn't log the student out of their own phone). Not yet: queue encryption at rest (LMS_AUDIT §3.3; prompt 61), pausing idle logout during an exam (prompt 50 must suspend it inside `<ExamMode>`), flush-before-logout warning (no queue exists yet; prompt 11).
52. **Settings screen** (`/settings`, any signed-in user): language, motion full / lite / off / auto (satisfies #47's WCAG 2.2.2 requirement), and the shared-device toggle (admins only; others see the state).

## 2026-11-24 — subject patterns move (Hassan, after trying the preview build)

47. **Subject tile patterns drift: the one approved looping decoration.** Hassan wants the Lahore-tile patterns on subject cards and pattern bands to move. Moment `patternDrift`: **full** = slow diagonal drift that loops (one tile per `duration.drift` = 8 s, linear, seamless because the pattern repeats); **lite** = one `duration.glide` (2 s) glide when the screen gains focus (e.g. Home opens), when a subject card is pressed and when a tile is set, then still; **off** = still. Never in exams (no pattern is drawn there) or on staff screens (no pattern). This relaxes DESIGN_SYSTEM §6 rule 3 ("no looping decoration") and the lite "fades only" rule for this moment only (`liteMovementExceptions`, tested). Safeguards: it moves only transform (one Animated.View per band, UI thread), stops when its screen loses focus, and 4 GB devices default to lite, so the loop only runs on stronger devices or by choice. WCAG 2.2.2 needs a way to stop motion longer than 5 s: the motion setting (and OS reduce-motion) does that, so **the Settings screen must expose full / lite / off / auto** (prompt 03 or later). Frame rate with several cards on a 4 GB Chromebook in full tier is **unverified** (TEST_PLAN P-4).

## 2026-11-23 — design system + motion tiers (session 02)

41. **Moti dropped; Reanimated 4 directly** (settles #38). Moti 0.30 (no release since Jan 2025) does not type-check against Reanimated 4, and everything we need (shared values, `withTiming`/`withSpring`, `withRepeat`, layout `exiting`) is in Reanimated, which runs on Android and web. Components never call Reanimated with their own numbers: they name a **moment** (`useEnterStyle('toast', visible, { translateY: 16 })`, `usePressMotion(depth)`, `usePulse('skeleton')`), and `ui/motion.ts` resolves it through the tier and exam mode. Only the props the resolved behaviour lists move, so lite automatically becomes a fade and off/exam snap to the end state. Removing Moti also removes a hoisted package that needed the Metro singleton pins.
42. **Tokens live in `packages/core/src/design/`** (`tokens.ts`, `motion.ts`), not in `apps/mobile/ui/` as #35 planned; `apps/mobile/ui/tokens.ts` re-exports them and `ui/motion.ts` adds the Reanimated glue. Why: they are pure data + pure functions (tier picker, `resolveMoment`, `presentationForGrade`, `textMetrics`, `isolateLtrRuns`, contrast), so they are unit-tested in Node with vitest (121 core tests) and stay React-free. `docs/design/tokens.draft.ts` and `scripts/verify-design-tokens.mjs` are deleted; their checks are `packages/core/test/design-*.test.ts`. CLAUDE.md's "use only the tokens in `apps/mobile/ui/motion.ts`" still holds (that file re-exports them).
43. **Icons: Lucide path data copied into `ui/icons.data.ts`** (30 icons, ~6 KB, ISC licence noted in the file) and drawn with `react-native-svg`, instead of `lucide-react-native`, whose barrel import would put ~1,900 icons in the bundle (cold-start budget on 4 GB Chromebooks). Mastery band shapes are our own SVGs (`MasteryShape`).
44. **Tier and exam rules in the components.** The tier is computed per subtree against the nearest theme's presentation, so staff screens default to lite (`(teacher)`/`(admin)` layouts set `presentation="staff"`). OS reduce-motion always wins, even over a gallery/user "full". `<ExamMode>` resolves every moment except `examTimerTick`/`examSaveIndicator` to none **and** drops decoration: no tile patterns (`PatternBand` becomes a plain fill) and no sticker shadows. A toast raised inside an exam keeps the exam's no-motion rule. Sticker shadows are a separate static layer so a press moves only the face (transform); selected fills in segmented controls fade as their own layer (colour cross-fade done with opacity). Root stack transition follows the tier (`default` / `fade` / `none`). Not built yet: the frame-drop sampler (prompt 62), haptics (moments list them; wire `expo-haptics` with the practice engine, prompt 31), the bundled Lottie burst (full-tier celebration falls back to a gentle spring until it exists).
45. **Sheet = React Native `Modal`**, bottom sheet on phones and a centred dialog from 600 px, closing on the close button, Android back, Esc (web) and the scrim. Not `@expo/ui` BottomSheet, because we need one look on Android and web. Closing is instant (no exit animation) for now.
46. **The gallery is a hidden route** (`/dev/gallery`): on in dev builds, or in a web/preview build exported with `EXPO_PUBLIC_DEV_GALLERY=1`; production redirects to `/`. Query params pick the starting state (`?lang=ur&theme=dark&tier=lite&p=kid&exam=1`) so screenshots can be scripted.

## 2026-11-23 — app scaffold (session 01)

Expo SDK 58 ships only Reanimated 4 (+ `react-native-worklets`), so "Reanimated 3" is no longer possible; the API we use (shared values, `withTiming`/`withSpring`, layout animations, `useReducedMotion`) is the same. Either way motion still goes through `ui/motion.ts` tokens and the tiers.
39. **Monorepo with the old app left at the root.** npm workspaces `apps/*`, `packages/*`; the old app keeps its root `package.json`, `App.js` and scripts, so `npm start` and EAS builds of the old app are unchanged. The new app's React 19 / RN 0.88 copies therefore live in `apps/mobile/node_modules` while some shared deps hoist to the root, so `apps/mobile/metro.config.js` forces a short list of singletons (react, react-native, reanimated, expo…) to resolve from `apps/mobile` while normal lookup stays on for everything else (one React, one RN in the bundle; nested versions respected) and `tsconfig.json` pins `react`, `react-native`, `react-native-reanimated` types (with Expo's `tsconfigPaths` turned off so Metro ignores those pins). Autolinking was checked: only SDK 58 native modules are linked. Moving the old app to `apps/legacy/` was not trivial (paths in `src/`, `scripts/`, EAS config); it can go once the old app is retired (OPS-remove-legacy), and the pins can then be removed.
40. **New app = same Play listing, new runtime.** `apps/mobile` keeps `com.school.app`, slug `school-app`, owner `ice_010` and EAS project `d0d4fed8-…`, with `orientation: default`, `versionCode: 2` and **version 2.0.0**. Because `runtimeVersion` follows the app version, OTA updates published from the new app (runtime 2.0.0) can never reach installed old-app builds (runtime 0.1.0), and vice versa. Nothing is published until Phase 1 parity. Before the first Play upload, check the highest versionCode the old app used in Play Console and start above it. Web export uses `output: "single"` (a plain SPA any static host can serve).
